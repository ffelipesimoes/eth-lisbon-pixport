# PIXPORT Agent — World IDKit Dev Test Path

> **For judges and developers who want to test World ID without a real World App / phone.**

---

## Overview

The PIXPORT agent requires a World ID proof to assign an **AllowanceTier** to the payer.
Tier controls how much the agent is allowed to spend:

| Verification Level | Tier | Max Spend |
|---|---|---|
| `orb` (Orb-verified human) | High | 1,000,000 token units |
| `device` (World App device) | Medium | 100,000 token units |
| `none` / unverified | Reject | 0 (rejected immediately) |

---

## Path A — Staging Simulator (recommended for judges)

**No phone required. Works in a browser.**

1. **Register a staging app** at the World Developer Portal:
   - Open [https://developer.worldcoin.org](https://developer.worldcoin.org)
   - Create a new app, select **Staging** environment
   - Create an Action named `pixport-payment`
   - Copy the `app_id` (format: `app_staging_…`)

2. **Set environment variables** in `packages/agent/.env`:
   ```env
   WORLD_APP_ID=app_staging_XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX
   WORLD_ACTION=pixport-payment
   WORLD_ENV=staging
   ```

3. **Generate a test proof** using the World ID Simulator:
   - Open [https://simulator.worldcoin.org](https://simulator.worldcoin.org)
   - Enter your `app_id` and action `pixport-payment`
   - Enter a **signal** = your Hedera payer account ID (e.g. `0.0.12345`)
   - Select verification level: `orb` for the high-tier test
   - Click **Generate Proof** → copy the JSON output

4. **Submit to the agent**:
   ```bash
   echo '{
     "brCode": "00020126330014BR.GOV.BCB.PIX0111123456789010208PIXPORT52040000530398654041.005802BR5913PIXPORT Demo6009Sao Paulo62070503***6304A1B2",
     "payerAccountId": "0.0.12345",
     "mandateId": "mnd-demo-001",
     "worldIdProof": {
       "proof": "<proof from simulator>",
       "merkle_root": "<merkle_root from simulator>",
       "nullifier_hash": "<nullifier_hash from simulator>",
       "verification_level": "orb",
       "signal": "0.0.12345"
     }
   }' | npm run pay -w packages/agent
   ```

5. **Expected output**:
   ```
   [Agent] Identity: verified (orb) → tier "Orb-verified human" (maxSpend: 1000000)
   [Agent] Allowance: remaining=…, approved=…
   ══════════════════════════════════════════
     Decision:    APPROVE
     Tier:        Orb-verified human (max: 1000000)
     HCS TX:      0.0.XXXXX@…
   ══════════════════════════════════════════
   ```

## Path B — Mock Proof (unit test, no network)

For automated CI testing, use a mock World ID response by setting:

```env
WORLD_ENV=staging
WORLD_APP_ID=app_staging_mock
```

And pointing to a local mock server (future Block 2 addition) or using `WORLD_MOCK=true`
to bypass verification and force a tier directly.

---

## Path C — Test the Rejection Flow

To verify the agent correctly rejects when allowance is exceeded:

1. Submit a valid World ID proof (orb tier) — agent approves
2. Submit another payment with the same mandate that would exceed the allowance
3. **Expected**: agent returns `ALLOWANCE_EXCEEDED` + logs rejection to HCS

This demonstrates **autonomous decision-making** — the agent enforces the on-chain limit
itself, without human intervention.

---

## Path D — Test Unverified Rejection

Submit a payment request **without** `worldIdProof`:

```bash
echo '{
  "brCode": "...",
  "payerAccountId": "0.0.12345",
  "mandateId": "mnd-demo-001"
}' | npm run pay -w packages/agent
```

**Expected**: agent immediately rejects with `TIER_INSUFFICIENT` — World ID required.

## Architecture Notes

- The `@worldcoin/idkit-standalone` package is installed as a dependency (browser SDK for
  the frontend to generate proofs). The agent itself calls the World ID **Cloud API**
  (`POST https://staging-developer.worldcoin.org/api/v1/verify/{app_id}`) to verify proofs
  server-side — no browser dependency in the agent runtime.

- For the staging environment, proofs generated by the World ID Simulator are valid and
  verifiable against the staging Cloud API without any physical device.

- `nullifier_hash` uniqueness prevents the same proof from being used twice. The Cloud API
  tracks this and returns an error on re-use — a natural Sybil protection.
